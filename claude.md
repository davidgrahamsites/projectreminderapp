# Project Reminder

A three-platform Apple app whose single purpose is to **keep the projects you're actively working
on fresh in your mind**. The **Apple Watch is the main surface**: at a user-set interval it fires a
**haptic**, and tapping it opens a **scrollable list of all your projects with one rotated to the
top**. The shown project, once dismissed, drops to the bottom — so each reminder promotes the next
project (round-robin). The **Mac app** is where projects are created/edited; the **iPhone app**
mirrors them and bridges Mac↔Watch.

See `context.md` for the *why*, `references.md` for sources, `restart.md` to resume cold,
`memory.md` for the running decision log, `agents.md` for the multi-agent build protocol.

## Architecture
- **SwiftUI**, three app targets sharing one Swift package, project generated by **XcodeGen** from
  `project.yml` (never hand-edit `.pbxproj`).
- `Packages/ReminderKit/` — shared pure-Swift core: `Model/` (Project, ReminderDocument),
  `Rotation/` (RotationEngine — the round-robin mechanic, unit-tested), `Settings/`
  (ReminderInterval/ReminderSettings), `Store/` (ReminderStoring protocol + InMemory + SwiftData),
  `Sync/` (SyncEnvelope + SyncTransport seam).
- `ProjectReminderMac/` — macOS authoring app (set projects, interval, LAN sync host).
- `ProjectReminder/` — iOS bridge app (mirror + relay Mac↔Watch).
- `ProjectReminderWatch/` — watchOS app (rotating list + interval haptics). The main point.
- **Sync:** local-first. Mac↔iPhone over LAN/cable via Bonjour (`LANTransport`), iPhone↔Watch via
  WatchConnectivity. Designed so a `CloudKitTransport` can be added later behind `SyncTransport`
  (iCloud needs a paid account — deferred). Conflict resolution: last-writer-wins on
  `ReminderDocument.version`.
- **Persistence:** per-device SwiftData store in the App Group `group.com.danielwang.projectreminder`.
- **Watch haptics:** repeating local notifications (`UNUserNotificationCenter`) — watchOS can't run
  free arbitrary background timers. Signing is a **free personal team** (7-day expiry; CloudKit
  unavailable).

## Build & Test Commands
```bash
# Prereqs: Xcode 26+, `brew install xcodegen`
xcodegen generate                                   # regenerate .xcodeproj from project.yml
swift test --package-path Packages/ReminderKit      # rotation/merge unit tests
xcodebuild -project ProjectReminder.xcodeproj -scheme ProjectReminderMac -destination 'platform=macOS' build
xcodebuild -project ProjectReminder.xcodeproj -scheme ProjectReminder \
  -destination 'platform=iOS Simulator,name=iPhone 17' build
xcodebuild -project ProjectReminder.xcodeproj -scheme ProjectReminderWatch \
  -destination 'platform=watchOS Simulator,name=Apple Watch Series 11 (46mm)' build
```
Always run `xcodegen generate` after adding/removing files or editing `project.yml`.

## Conventions
- ReminderKit stays UI-free (no SwiftUI/UIKit/AppKit) and unit-tested.
- UI binds to the `ReminderStoring` protocol, never a concrete store; sync goes through
  `SyncTransport`. Don't bake cloud/transport assumptions into views.
- Only the **Mac** target integrates the App Opener Hub data bus (`127.0.0.1:9800`,
  fire-and-forget on sync/export). iOS/watch can't reach localhost — do NOT add Hub calls there.
- Targets iOS 17 / watchOS 10 / macOS 14. Bundle base `com.danielwang.projectreminder`.
